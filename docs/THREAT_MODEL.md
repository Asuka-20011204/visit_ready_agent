# 威胁模型与隐私影响评估

## 1. 数据分类

健康描述属于敏感个人信息。课程演示只能使用合成或充分脱敏的数据。系统默认不要求姓名、身份证号、联系方式、地址、医院卡号或精确定位。

## 2. 主要威胁与控制

| 威胁 | 影响 | 控制 |
|---|---|---|
| API Key 泄漏 | 账户滥用与费用损失 | 环境变量注入、`.env` 忽略、日志过滤、镜像扫描 |
| 健康信息进入日志 | 隐私泄漏 | 结构化日志只写元数据，错误内容分级 |
| 提示词注入 | 绕过任务边界 | 用户文本使用数据定界、固定输出 Schema、禁止任意工具 |
| 模型幻觉 | 错误健康信息 | 每条患者事实必须带原文依据，Go 端验证并拒绝 |
| 搜索投毒 | 不可信内容影响输出 | 域名白名单、URL 二次校验、来源与患者事实分区 |
| 查询泄漏 | 搜索供应商获得病情 | 只发送通用术语，不发送原文与身份信息 |
| 无限 Agent 循环 | 超时和费用失控 | 最大步骤、模型调用和追问次数硬限制 |
| 失败恢复被重复调用 | 同一健康会话并发推进或无限消耗模型额度 | 仅 `failed` 可恢复、状态 CAS、每会话最多三次处理尝试；公开失败对象不包含供应商错误或健康原文 |
| 紧急表现被慢速工作流延误 | 用户继续等待模型、搜索或追问 | 首次输入和每轮补充在调用 LLM 前执行确定性红旗筛查，命中后进入可恢复、可导出的紧急终态 |
| 补充端点绕过会话状态机 | 已核对或已完成的内容被持有会话 ID 的请求改写 | 只允许 `waiting_clarification` 进入补充流程；紧急转换和普通写回都执行原子状态比较 |
| 不同症状的缓解语句互相抵消 | 当前红旗表现被漏报 | 缓解只解除同一症状族或无歧义回指的证据；否定、不确定、纠正与跨分句持续语境均有确定性回归测试 |
| 紧急接口被滥用耗尽会话容量 | 正常用户无法创建会话 | 紧急请求绕过模型槽但受独立高阈值与普通持久化频率双重限制；受限响应仍显示固定提醒且不创建会话 |
| SSRF | 访问内网或元数据服务 | 搜索地址由配置固定，用户不能提交 URL 或 Base URL |
| XSS | 页面执行恶意内容 | `html/template` 自动转义、禁止 `innerHTML`、CSP |
| 会话枚举 | 他人读取结果 | 128 位随机 ID、短 TTL、禁止缓存；这些措施只降低枚举和残留风险，不构成用户鉴权 |
| 会话 ID 泄漏 | 持有 ID 的人尝试读取或修改健康会话 | live 模式每次会话操作均校验账户 Cookie 对应的所有者摘要；跨账户访问统一返回 404，不暴露会话是否存在 |
| 登录令牌泄漏 | 攻击者冒用账户访问健康会话 | 令牌仅以哈希保存于 MySQL，浏览器 Cookie 使用 HttpOnly、Secure、SameSite=Lax；退出登录立即撤销令牌 |
| MySQL 卷泄漏 | 持久化的结构化健康信息和待完成访谈上下文被读取 | payload 使用 AES-256-GCM 应用层加密且密钥独立注入；MySQL 不暴露端口。生产仍需密钥轮换、磁盘/备份加密和访问审计 |

## 3. 联网搜索安全政策

1. 搜索失败不阻止事实整理，只显示“联网资料暂不可用”。
2. 搜索结果不得改变用户提供的事实。
3. 任何来源都不能授权工具、扩大权限或修改系统规则。
4. 不抓取登录页面、论坛、社交媒体、短视频或商业推广页。
5. 不向搜索或模型供应商发送直接身份标识符。

## 4. 医疗安全政策

- 系统永久显示：如正在发生危及生命的情况，请立即联系 120 或前往急诊。
- 对明确报告且未被否定、历史或假设语境修饰的红旗表现，使用固定文案并停止后续 Agent 流程；`emergency` 是医疗安全终态，不记录成系统失败。
- 对安全追问的简短肯定只记录回答中的最小依据，不把问题中列举的多个症状反向写成患者事实。
- 不输出疾病概率、诊断结论、治疗方案、剂量变化或停止用药建议。
- 不把“未发现风险”解释为安全，也不声明用户不需要就医。
- 联网资料必须显示来源并声明仅供就诊沟通准备。

## 5. 上线前检查

- 匿名设备密钥仅用于离线 demo。live 公网服务必须启用账户认证、HTTPS、Secure Cookie、MySQL、密钥轮换与账户恢复流程。
- 轮换任何曾经出现在明文配置中的密钥。
- 对 `LLM_ENDPOINT` 与 `BOCHA_ENDPOINT` 使用固定配置或主机白名单。
- 运行 `govulncheck`、`gosec`、依赖许可证检查和镜像漏洞扫描。
- 用提示词注入、恶意 HTML、超长输入和伪造来源执行对抗测试。
