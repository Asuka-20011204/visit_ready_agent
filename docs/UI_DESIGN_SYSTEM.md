# VisitReady UI 设计系统

更新日期：2026-09-04

## 方向：浅色空气线程，而不是白框工作台

界面采用接近自然光的薄荷纸面、暖珊瑚几何侧翼、氧化青绿控件和少量暖铜强调。目标是把 Codex 式可恢复线程与 Sakura 式空气感、相邻色层和有机错位结合：安静、易读，能够表达重要状态，又不过度制造焦虑。主画面不使用整块深色导航、横向色带或白色卡片阵列。

Sakurairo 只影响半透明层次、轻柔内高光、一致圆角，以及 `cubic-bezier(.07,.53,.65,.95)` 动效曲线。粉色主题、粒子、大范围光晕和博客卡片布局明确排除。

## 颜色 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#f3f8f5` | 明亮薄荷页面底材 |
| `--canvas-warm` | `#f7eae6` | 暖珊瑚几何侧翼 |
| `--rail` | `rgba(247, 250, 248, .76)` | 透明导航层 |
| `--surface` | `rgba(255, 255, 255, .52)` | 临时或分组内容 |
| `--surface-raised` | `rgba(253, 254, 251, .90)` | 可操作 artifact 与 Composer |
| `--surface-inset` | `rgba(47, 109, 97, .07)` | 局部悬停和内嵌提示 |
| `--ink` | `#26332f` | 主文字 |
| `--muted` | `#55635e` | 辅助文字 |
| `--quiet` | `#5f6c67` | 元数据 |
| `--accent` | `#2f6d61` | 导航和 Agent 控件 |
| `--accent-warm` | `#a4554c` | 人工决策和关键操作 |
| `--success` | `#3f7a63` | 完成状态 |
| `--warning` | `#9a623f` | 中断和 Demo 状态 |
| `--danger` | `#a34f50` | 紧急和失败状态 |

禁止纯白大底和整页深色。薄荷色负责主要面积，珊瑚色只形成不规则侧翼，青绿识别 Agent，暖铜提示人工注意，红色只用于安全和错误。颜色不单独承担层级，必须同时使用位置、脊线、字号或文字。

## 表面层级

1. Canvas：明亮薄荷纸面与极轻有机线条，右上用珊瑚色斜切色面破除单调。
2. Navigation：透明导航层，以间距、细线和 active 色脊区分，不做深色卡片容器。
3. Message：沿对话脊线展开；Assistant 内容无框，User 只使用一小块暖纸气泡。
4. Run record：仅保留上下分隔线，不使用外框和悬浮阴影。
5. Artifact：线程中生成的浅薄荷文件页，以左侧色脊和右上折角表达归属，不使用四周描边或硬直角白卡。
6. Composer：轻盈悬浮托盘，以左侧暖铜色脊、柔和阴影和不对称圆角表达可操作性，不使用白色描边。

不嵌套装饰卡片。Artifact 内的行使用色调差异分组，不重复白框和阴影。

## 几何与间距

- 主阅读宽度最大 `57.5rem`。
- 历史栏为 `14rem`，可收起至 `4.5rem`。
- 控件圆角 6–8px，Composer/Artifact 为 10–12px；容器不使用超大胶囊。
- 间距节奏：4、8、12、16、24、32、48px。
- 最小点击区域：桌面 36px，触摸 40px。
- 说明文本保持约 60–72 个字符的可读行长；事实内容允许自然换行。

## 字体

使用本地 `Microsoft YaHei UI`、`Segoe UI Variable`、`Noto Sans SC` 回退链；标题优先使用本地宋体衬线形成临床信笺感。CSP 不允许外部字体请求。标题依靠衬线、字重和留白建立层级，不使用营销页式巨型字号。状态数字与时间使用等宽数字。

## 状态语法

| Agent 状态 | 视觉方式 | 文案要求 |
| --- | --- | --- |
| Idle | 空线程与可用 Composer | 提供三个以事实为导向的输入起点 |
| Running | 三点动效，禁用发送 | 说明正在执行的动作，不宣称 token streaming |
| Interrupted | 暖铜标记，显示追问或核对控件 | 明确说明用户需要提供什么 |
| Completed | 绿色标记与导出动作 | 说明输出内容及过期限制 |
| Degraded | Run record 内的暖铜标记 | 不隐藏降级路径 |
| Failed/timeout | 靠近动作的红色内联错误 | 保留输入，允许重新提交 |
| Expired | 替换线程行动区域 | 说明数据已清除，并提供新建动作 |

## 交互规则

- 只动画化 opacity 与 transform，常规时长 180–320ms；进入和抬升使用 Sakurairo 曲线。
- 全局遵守 `prefers-reduced-motion`。
- 每个 hover 状态都要有可见的键盘 focus 对应状态。
- Enter 提交，Shift+Enter 换行。
- 请求必须超时，不能无限保持 busy；失败后保留用户输入。
- 恢复的会话必须播报恢复状态，并重新要求核对事实。
- 来源链接必须为 HTTPS，并使用 `noopener noreferrer`。
- Run record 永远不显示思维链、原始提示词或隐藏模型数据。

## 响应式规则

860px 以下，历史栏变成横向紧凑 thread strip，顶栏不再形成色带；630px 以下，欢迎区和路径列表改为单列，元数据优先让位给主要内容，Artifact 改为单列，Composer 保持稳定发送目标。文字放大到 400% 时页面不得产生水平溢出。

## 智能访谈状态组件

- 访谈进度使用 3px 横向脊线和“已明确 / 待处理”数字，不用进度圆环或仪表盘。
- 会话摘要正文维持 15px、约 68 字符行长；确认项使用小圆点的连续列表，不包白框。
- 未知项使用低饱和暖纸表面和 3px 暖铜脊线；冲突项使用两段并排原话，移动端自然折为单列。
- 不确定、跳过、冲突属于信息状态，不使用错误红色；红色只保留给真实安全信号与请求失败。
- “补充其他信息”是 Composer 内的文字动作，不与主要发送按钮竞争。
