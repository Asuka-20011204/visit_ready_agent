# 诊前助手 Agent - 产品需求文档

## 1. 背景

门诊沟通时间有限，患者常把症状、时间变化、已用药物和检查结果记录在不同位置，现场容易遗漏。系统把用户提供的零散信息整理为可核对的一页诊前摘要，并通过受限联网检索补充可信来源中的就诊准备信息。

## 2. 产品边界

系统负责：

- 提取用户明确提供的事实并保留原文依据。
- 发现影响沟通完整性的缺失信息并进行一次追问。
- 在可信域名中检索通用健康术语和就诊准备资料。
- 生成可编辑、可确认、可导出的就诊摘要。

系统不负责：

- 诊断疾病、估计疾病概率或判断用户“无需就医”。
- 推荐药物、剂量、停药或替代专业医疗意见。
- 自动挂号、联系医院或向第三方发送患者资料。
- 将个人健康记录用于训练、画像或长期保存。

## 3. 目标用户与核心旅程

目标用户是希望在门诊前把自身情况讲清楚的普通成年人。

核心旅程：

1. 用户阅读隐私说明和安全边界。
2. 用户输入脱敏后的症状、时间、用药和检查信息。
3. Agent 提取事实、验证原文依据并判断是否需要追问。
4. 用户回答最多一轮补充问题。
5. Agent 以不含个人信息的查询检索可信来源。
6. 用户核对并编辑摘要。
7. 用户确认后导出 Markdown 文件或使用浏览器打印。

## 4. 功能需求

### P0

- 单页 Web 工作台，支持输入、加载、追问、核对、错误和完成状态。
- OpenAI 兼容模型 API 的真实调用。
- 事实提取结果必须包含原文依据。
- Go 端校验输入、模型 JSON、原文依据和禁止内容。
- 联网检索只允许配置的可信域名，查询不得携带原始病历或直接身份信息。
- 每条外部资料显示标题、域名、URL 和摘要。
- Agent 最大 6 步、最多 3 次模型调用、最多一轮追问。
- 内存会话 30 分钟过期，默认不落盘。
- Markdown 导出、健康检查和结构化日志。

### P1

- SSE 展示 Agent 动作事件。
- Docker Compose 一键启动。
- Kubernetes Deployment、Service 与 Secret 示例。
- 评测命令对固定脱敏样例统计结构化成功率和证据通过率。

## 5. 非功能需求

- 单次输入 20 到 6000 个 Unicode 字符，请求体最大 32 KiB。
- 外部 AI 与搜索请求分别设置超时，总请求上限 45 秒。
- 不记录用户原文、模型完整响应、搜索查询或 API Key。
- 页面键盘可操作，焦点可见，正文对比度达到 WCAG AA。
- Windows 单文件与 Linux 容器均可构建。

## 6. 验收标准

- 20 条标注样例中至少 19 条能得到合法结构化响应。
- 所有保留事实都能在输入中找到原文依据。
- 任何包含诊断、处方或无依据事实的模型结果均被拒绝或移除。
- 搜索请求只访问允许域名，且不包含手机号、身份证号、邮箱或用户原文。
- API Key 缺失、429、超时、非法 JSON、空输入和超长输入都有明确错误。
- `go test -race ./...` 通过，核心包覆盖率不低于 80%。
